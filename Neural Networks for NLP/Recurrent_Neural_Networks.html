Recurrent Neural Networks

Give the network a memory, and language starts to make sense
Reading a sentence, one word at a time

A feedforward network reads a fixed box of numbers and forgets everything afterwards. Language is not a box. It arrives word after word, and the meaning of the next word depends on every word before it. Recurrent networks fix this with one simple idea: keep a memory, and update it at every word.

Why a feedforward network is not enough

1 · The input size is frozen

A feedforward layer holds one weight per input position. Train it on 5 words and you cannot feed it 30. Real sentences have no fixed length.

2 · There is no memory

Every example is handled alone. When the network reaches word 12 it keeps no trace of word 3. Pronouns, negation and agreement all need that trace.

3 · Order is thrown away

A bag of words gives the very same vector to two sentences that mean opposite things.

dog bites man

Order changes the memory → different answer.
The question of this course: how can one network read an input of any length and still remember what it read at the beginning?

The recurrent idea: one cell, reused

An RNN is not a long network. It is a very small network applied again and again – once per word – carrying a vector called the hidden state from each step to the next. The two pictures below show the same model.

One box. The orange arrow feeds the memory back into itself.
The same box copied once per word. All copies share exactly the same weights.

Weight sharing

The unrolled picture looks deep, but every layer uses one single set of weights. Two results: the parameter count does not grow with sentence length, and whatever the model learns at position 2 is reused for free at position 40.

The hidden state is a summary

ht is a fixed-size vector – say 256 numbers. It must squeeze everything useful from words 1 to t. That squeeze is the strength of the model, and later in this chapter it becomes its weakness.

How an RNN learns: backpropagation through time

Training is ordinary backpropagation applied to the unrolled network. Because the weights are shared, every copy sends back its own gradient and all of them are added together into one update. Press the button and watch the three stages.

idle
Stage 1 runs the sentence forward, stage 2 measures the error, stage 3 sends the blame backwards through every step.

Forward

Read the whole sequence, keep every hidden state in memory — they are all needed later.

Loss

Compare the prediction with the true label. Usually cross-entropy, summed over all time steps that produce output.

Backward

Walk from the last step to the first, multiplying by Wh at every hop. Add up the gradient contributions and update once.

Two consequences. Memory grows with the sentence length, because every hidden state must be kept — which is why long documents are cut into chunks, a trick called truncated BPTT. And because the signal shrinks at every hop, a plain RNN never really learns that word 40 depends on word 2. That single weakness is the reason gates were invented.

LSTM: give the memory a set of gates

Hochreiter & Schmidhuber, 1997. A plain RNN overwrites its memory at every word. The Long Short-Term Memory cell instead keeps a second vector, the cell state ct, and edits it gently with small valves called gates. A gate is just a sigmoid layer producing a number between 0 and 1 for each dimension: 0 means "block", 1 means "let it pass".

The memory highway. ct travels from step to step with only a multiply and an add — no matrix, no tanh. That straight road is what lets a gradient survive hundreds of steps.

What LSTM gained

  • Long-range dependencies really do get learned
  • Gradients survive because of the additive highway
  • The model decides per word what to keep and what to drop
  • Ruled machine translation, tagging and speech for two decades

What it cost

  • Four weight matrices instead of one — four times the parameters
  • Slower training, heavier memory use
  • Still strictly step by step, so no parallel computing
  • Many moving parts to tune
GRU: the lighter cousin

Cho et al., 2014. The Gated Recurrent Unit keeps the gating idea but throws away the separate cell state and uses two gates instead of three. Fewer parameters, faster training, and very often the same accuracy.

1 One memory instead of two

c and h are merged. The cell carries a single state vector, so there is no highway to read from and no output gate to control it.

2 Forget and input are tied together

One update gate z decides both sides of the deal: the fraction to keep and the fraction to replace. They always add up to 1.

GatePurpose
Update gateControls memory retention and update
Reset gateControls forgetting of previous information

So the cell answers only two questions at each word: what should I forget? and what should I remember? Setting the reset gate near 0 lets it start a fresh thought — handy at a sentence boundary.

Why GRUs train faster

Compared with LSTMs, GRUs have
  • Fewer gates
  • Fewer matrix multiplications
  • Fewer parameters
  • Less memory usage
This results in
  • Faster convergence
  • Lower computational cost
  • Smaller models

When should we use GRUs?

A GRU is usually the better pick when:

Training data is limited

Fewer parameters means less to overfit.

Fast training matters

Fewer matrix multiplications per step.

Memory is tight

Only one state vector to store and move.

The system is real time

Lower cost per token keeps latency down.

Typical places you will meet one: chatbots speech recognition sentiment analysis sequence classification text generation

Counting the parameters

A recurrent layer always needs the same three things per gate: a matrix for the input, a matrix for the previous state, and a bias. So one gate costs h×d + h×h + h. Multiply that by the number of gates: 1 for an RNN, 3 for a GRU, 4 for an LSTM.

Making it deeper: stacked RNNs

One recurrent layer reads the words. A second layer reads the first layer's hidden states instead of words. The lower layer picks up short local patterns; the upper one builds phrase-level meaning.

What gates could not fix

Gating solved the gradient problem. Three problems stayed — and they are exactly the problems the next chapter's architecture was built for.

Limit 1

The encoder bottleneck

In an encoder–decoder, the whole source sentence is squeezed into one final vector. A 40-word sentence gets the same number of slots as a 4-word one, so translation quality falls off a cliff as sentences grow.

Answer: attention — let the decoder look back at every encoder state.

Limit 2

No parallel computation

ht needs ht-1. A 500-token document means 500 steps that no GPU can run at the same time. Training on billions of words becomes impossibly slow.

Answer: self-attention processes every position at once.

Limit 3

Distance still costs

To connect word 1 with word 200, information must pass through 199 cells. Better than a plain RNN, but still a long fragile chain, and still one fixed-size vector doing the carrying.

Answer: attention links any two positions in a single hop.

Where recurrent models are still the right choice

Streaming input
Tokens arrive one at a time and an answer is needed immediately.
Small devices
A GRU is far smaller and cheaper than a transformer.
Small training sets
A transformer would simply overfit.
Very long signals
Raw audio, where attention cost grows with the square of the length.
Key takeaway

One small cell, applied again and again, with a vector of memory passed along the chain — that is the whole recurrent idea. Plain RNNs proved the idea but lost the signal over distance. Gates gave the memory a set of valves and bought two decades of state-of-the-art NLP. What they never bought was speed, because time can only be walked one step at a time. Removing that constraint is what the next chapter is about.
